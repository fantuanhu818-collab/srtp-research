更新日期：2026-11-19　负责人：B（李宇白）　复核人：A（胡嘉琪）

本文件是AI技能变量的**总方案**，结构与A的《职业类型变量构建方案》《非AI技能构建方案》一致。各步骤的详细过程和数字依据见：

- `docs/AI技能识别调整方案与对接_2026-11-16.md`：v0.1.1到v0.2每一步怎么做、为什么；
- `docs/AI技能标注对齐说明_v0.2.md`：筛词和人工标注的判断口径；
- `docs/AI技能词典_v0.2_词表.md`：264个词的完整词表；

- `docs/AI技能词典_v1.0_词表.md`：**终版**词典（240个词，§8微调一轮后冻结）。

## 一、这一步的目标

判断每条招聘广告是否**要求求职者具备AI技能**，生成0/1变量`ai_skill`，作为基准回归的核心解释变量。

例如：

```Plain Text
熟悉PyTorch，负责目标检测模型训练与部署        → ai_skill = 1
能使用ChatGPT辅助文案写作者优先                → ai_skill = 1（生成式AI）
我们是一家专注于人工智能的企业；负责客户开发    → ai_skill = 0（AI只在公司介绍里）
熟练使用PS、AI等设计软件                       → ai_skill = 0（AI指Illustrator）
```

同时生成几个辅助变量，用于描述统计和稳健性检验：宽泛版`ai_skill_broad`、生成式`ai_genai`与传统`ai_traditional`、至少两类AI词版`ai_skill_2cat`、连续强度`ai_intensity`。

`ai_skill`只表示广告**写出了**AI技能要求。回归结果只能解释为相关关系，不能写成“AI技能导致工资提高”。

|---|---|---:|---|

|条件|常指AI，也常有别的意思（如机器视觉）|89|会，但要有另一个**不同的**严格词或条件词作证|

|复核|需要人工看（如数据标注）|3|不会，只打`ai_review_flag`|

其中生成式AI词44个，传统AI词212个。

## 四、具体识别方法

整个识别过程分为四层，全部是确定性规则，同样的输入永远得到同样的结果。

### 第一层：切句并区分公司介绍

按句号、分号、换行和“1、”“（2）”这类编号切句，再判断每句属于哪一段：

- 遇到“任职要求”“岗位职责”等段落标题，进入**要求段**；
- 遇到“公司介绍”“福利待遇”等段落标题，进入**介绍段**；
- 不在明确段落里时，按句中线索判断：有“致力于”“是一家”“总部位于”等强线索、且没有“熟悉”“负责”等要求线索的句子，算公司介绍。

公司介绍句里的AI词一律不计。这是解决“AI公司的会计岗”这类误判的主要手段。

### 第二层：按层级匹配词典

- 严格词：出现在非介绍句中即计入；
- 条件词：要和另一个**不同的**严格词或条件词同时出现才计入；没搭配上的记在`ai_conditional_terms`，只计入宽泛版；
- 宽泛词：只在带要求或职责线索的句子中计入宽泛版。

英文缩写按整词匹配：ML不匹配HTML、500ml，AI不匹配MAIL。

### 第三层：排除规则和否定表达

**排除规则**（17条，都写得很窄：同一句匹配到排除条件时，这一句不计该词）：

```Plain Text
LLM 指法学硕士              → 同句有“法学”“法律”“律师”时不计
PS、AI绘图里的 AI           → 指Illustrator，不计
3D、动画岗位的“模型微调”    → 同句没有大模型、深度学习等词时不计
城市智能体、GPT会议         → 产品名或会议名，不计
```

每条排除规则都在全样本上统计过排除了多少条、抽查有没有误伤，误伤就收窄（见`outputs/qc/ai_exclusion_check_v0.2.csv`）。

**否定表达**（与A的非AI技能口径一致）：

- AI词前面6个字以内有“无需、不要求、不需要、无须、不必”等，或后面紧跟“不作要求、非必须”，该处不计；
- “者优先”照常计1，企业已经表达了偏好；
- “不限”**不算**否定。全样本核对发现，“OpenCV等不限”“AI能力(不限)”的意思都是“不限于”。

在全样本中，这条规则实际改变的广告数为0（见`outputs/qc/ai_negation_title_impact_v0.2.csv`），保留它是为了和非AI技能口径一致。

### 第四层：汇总为变量

```Plain Text
ai_skill       = 有计入的严格词或有搭配的条件词
ai_skill_broad = ai_skill = 1，或有宽泛词、没搭配的条件词
ai_genai / ai_traditional = 计入的词属于生成式 / 传统AI
职位描述缺失且标题没有命中 → 缺失（不能编码为0）
```

岗位名称里的严格词照常计入`ai_skill`（原方案口径；是否改为“标题不单独决定”列在待决定事项里，程序保留了开关`title_counts_strict`）。

## 五、人工标注如何用于检验和修改规则

### 分层抽样

按ChatGPT发布前、后两个时期，各抽7层，共360条：

|层|条件|每个时期|主要检验|
|---|---|---:|---|
|严格命中|`ai_skill`=1|50|查准率|
|只命中新词|命中词全部来自Word2Vec新增|20|新词质量|
|只有没搭配的条件词|`ai_skill`=0|30|降级是否过严|
|只命中宽泛词|`ai_skill`=0|30|查全率|
|只在介绍句命中|AI词只在公司介绍里|10|查全率|
|未命中的技术岗|岗位名称含工程师、开发、算法等|15|查全率|
|未命中的其他岗位|其余|25|查全率|

查准率和查全率按各层总体数加权换算到全样本（`outputs/qc/ai_annotation_v0.2_strata.csv`），两个时期分别报告。

### 人工和Agent各做什么

参照A的职业复核：**人只做核心判断，Agent补其余部分，Agent不能改人的判断。**

|环节|人做|Agent（程序）做|
|---|---|---|
|标注|只看原文，填1/0/9、AI类型、备注标签（Excel下拉）|—|
|交回前检查|—|检查漏填、取值、AI类型与标注是否矛盾|
|一致性|两人讨论分歧|算一致率、kappa，列分歧清单|
|误判漏判|—|对照原文填错误原因代码；认为人工可能标错的，只写“建议复核”|
|改规则|两人确认改哪些|按确认结果改词典、补测试、全量重跑|

标注表：`<analysis_root>/ai_annotation_v0.2/标注表_A.xlsx`、`标注表_B.xlsx`（含原文，不进Git）。每人205条，其中50条两人都标，随机混在表里。

### 错误原因代码

`company_intro`、`homonym`、`generic_mention`、`negation`、`conditional_unpaired`、`missing_term`、`exclusion_overreach`、`exclusion_missing`、`tool_use`、`label_dispute`，含义见对齐说明3.10节。程序只接受这10个代码。

### 只微调一轮

下面的规则在标注开始前写定，看到结果后只按这些规则调整，**只调一轮**：

|标注结果|调整|
|---|---|
|严格版查准率低于85%（任一时期）|找出误判最多的词，降一级|
|“只有没搭配的条件词”层中，人工判AI比例≥70%|门槛过严：条件词门槛从30%降到20%|
|“只命中新词”层中，人工判AI比例<50%|删除在误判中出现过的新词|
|同一错误原因代码出现多次|按代码对应的方式改规则；只出现一次的记录在案、不改|
|某层的人工判AI比例在两个时期差距很大|在文档中报告，不分时期设规则|

原则是只改统一规则后重跑全样本，不逐条手改结果。微调和检验用的是同一批样本，微调后的查准率会偏乐观，中期报告以**微调前**的指标为准。

## 七、验收标准

正式冻结前检查：

1. 每年输出行数等于输入行数，合计5,235,461条；
2. `source_record_id`唯一、非空、字符串；
3. `ai_skill`只取0、1或缺失；职位描述缺失不编码为0；
4. 与`confirmed_core_v2`一对一连接，`13_check_ai_merge.py`输出`AI_MERGE_GATE=PASS`；
5. 两人共同标注样本kappa不低于0.7；
6. 严格版查准率原则上不低于85%，两个时期分别报告；
7. 单元测试全部通过（每条排除规则至少一个“该排除”和一个“不该排除”的例子）；
8. 修改规则后必须重跑2018—2025年全样本，而不是只修人工样本。

## 八、与其他变量的接口和最终合并

与A的非AI技能变量共同遵守三条接口规则：

1. **同一个词不能同时出现在两套词典中。** scikit-learn、OpenCV、TensorFlow、PyTorch等只在AI词典；Python、SQL、Matlab、Spark、Hadoop等一般编程和数据工具不进AI词典（目前AI词典中均没有），由`skill_software`负责；
2. 双方使用相同的`source_record_id`；
3. 两套结果允许同时为1，合并时不能写成“AI为1则软件技能为0”。

最终合并（由A完成）：

```Plain Text
confirmed_core_v2
＋ occupation_v1.0
＋ ai_skill_v1（终版）
＋ 三类非AI技能变量
＝ sample_base_v1
```

|触发的规则|标注结果|调整|

### 已知局限（v1.0不再修改）

剩余误判主要来自：原有严格词的上下文问题（OpenCV、机器学习、NLP、大模型裸词），同形词（“大模型体量”“计算机视觉设计”），AI数据标注，AI词只出现在专业列表中，可选项列举（“以下一种或多种”），公司介绍未识别。漏判主要是AI工具使用（AlphaFold、“利用AI工具设计”）和个别新词（具身智能）。这些不再改词典；对结论可能有影响的，在稳健性检验中另构造变量（如去掉专业列表和可选项命中的版本），主变量不变。

## 十一、本轮不做的事

- 不用大语言模型或机器学习分类器识别AI技能：标注样本太少，不足以训练和检验，可留作以后的稳健性检验；
- 不使用AI暴露度指数（Felten、Webb、Eloundou等）：它衡量职业受AI影响的程度，不是广告是否要求AI技能；
- 不修改`cleaned_v1`和`confirmed_core_v2`。
