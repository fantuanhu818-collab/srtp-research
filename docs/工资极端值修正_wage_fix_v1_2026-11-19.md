# 工资极端值与单位错误修正：wage_fix_v1 → v2（2026-11-19，A线）

本文记录工资修正表的依据、规则、结果和用法。数据结论已由DuckDB独立复算，**`cleaned_v1`和`confirmed_core_v2`均未改动**，修正结果单独放在`features\wage_fix_v1`（三组年薪/量级修正）和`features\wage_fix_v2`（在v1基础上把“面议”占位值置缺失）。

## 一、为什么需要单独一张表

`cleaned_v1`的工资规则只有四条：端点必须可转数值且>0、双端点无效删除、单端点有效保留、上下限颠倒交换。它不检查单位，也不检查数量级，因此下面三类成批错误原样进入了`confirmed_core_v2.wage_mid`，并会继续传给以后的分析数据。

|类型|年份×平台|规模|证据|
|---|---|---:|---|
|年薪误录为月薪|2018年平台11|118,329条（月薪≥3万）|3万—6万区间同年同岗位配对倍数为12.5，且该区间2019年为0条|
|年薪误录为月薪|2021年平台72|7,199条（月薪≥6万）|6万以上配对倍数12.57；3万—6万配对仅2.29，属正常高月薪|
|整平台量级放大约10倍|2018、2019年平台64|547 + 9,855条|分位点比值8.46—11.88，10倍拟合最优；同企业2019/2020中位比10.77|

合计修正**135,930条**，占全样本2.60%。门槛、倍数的完整证据写在`config/wage_fix_rules_v1.json`。

## 二、修正规则

|规则ID|年份|平台|条件|处理|条数|
|---|---:|---|---|---|---:|
|`annual_div12_p11_2018`|2018|平台11|`月薪代表值 ≥ 30000`|÷12|118,329|
|`annual_div12_p72_2021`|2021|平台72|`月薪代表值 ≥ 60000`|÷12|7,199|
|`scale_div10_p64_2018`|2018|平台64|`月薪代表值 ≥ 10000`|÷10|547|
|`scale_div10_p64_2019`|2019|平台64|`月薪代表值 ≥ 10000`|÷10|9,855|

三条判据说明为什么阈值不是统一的一个数：

1. **平台11的界在3万，不是6万。** 2018年平台11的3万—6万区间有5,772条，而同一平台2019年该区间为0条、6万以上也为0条；同时2万—3万区间两年分别为12,198和12,739条，说明2万—3万是正常月薪。用同企业同岗位配对，3万—6万组相对正常组的倍数中位数是12.5（上下四分位都是12.5），6万以上组是14.67。若沿用6万门槛，这5,772条年薪会被当成月薪保留。
2. **平台72的界在6万。** 2021年平台72的3万—6万区间有7,905条，配对倍数只有2.29，是正常的高月薪；6万以上配对12.57，才是年薪。
3. **平台64不是年薪，是整平台放大。** 2019年平台64只有5条低于1万元，其余整段上移；与2020年同平台分位结构拟合，10倍的误差平方和0.081，9倍0.125，11倍0.137，12倍更差。同企业2019/2020中位工资比为10.77。因此按÷10还原，并保留最低的6,500元记录（视为已是月薪）。

## 三、输出与字段

路径：`D:\SRTP\工作数据\features\wage_fix_v1`，每年一个Parquet（2018—2025，共8个）+ `manifest.json`。

|字段|说明|

配套QC：`outputs/qc/wage_fix_v1_summary.csv`（年度汇总）、`wage_fix_v1_distribution.csv`（前后分布）、`wage_fix_v1_remaining_extremes.csv`（残留高值）、`wage_fix_v1_validation.md`（独立复核报告）。

## 五、怎么用

Parquet按年读取后与底表左连接：

```python
import pandas as pd
core = pd.read_parquet(r"D:\SRTP\工作数据\features\confirmed_core_v2\jobs_2018_confirmed_core.parquet")
fix = pd.read_parquet(r"D:\SRTP\工作数据\features\wage_fix_v1\jobs_2018_wage_fix.parquet")
df = core.merge(fix, on="source_record_id", how="left", validate="one_to_one")
df["wage"] = df["wage_mid_fixed"]
df["ln_wage2"] = df["ln_wage_fixed"]
```

Stata里等价的合并（先把两张Parquet导出为DTA）：

```stata
merge 1:1 source_record_id using "wage_fix_v1.dta", keep(master match) nogen
gen wage     = wage_mid_fixed
gen ln_wage2 = ln_wage_fixed
```

口径提醒：
- 描述统计的均值、标准差、P99一律用`wage_mid_fixed`；用原值会把全样本均值高估约32%；
- 基准回归用`ln_wage_fixed`；两者之差只影响水平值，对AI—非AI对数差的影响很小（2018年约0.04）；
- 需要“未修正口径”做稳健性时，直接用`wage_mid_orig`，两列在同一张表里，不会串；
- 建议在回归表中保留`wage_fix_flag`，做一次剔除敏感样本的稳健性检验。

## 九、与B的诊断不一致的地方

1. **平台11阈值应由6万降到3万**，否则漏掉5,772条年薪（B的诊断表里2018年>6万为112,557条，实际应修正118,329条）；
2. **2019年平台64是整平台约10倍量级错误**，不是B所说的“样本量较小的平台”，共9,860条、46.76%月薪>10万，需要单独规则；B建议的“≥6万÷12”在这一块不适用；
3. B的试算“共119,477条”对应的是“仅平台11和平台72、门槛6万”，按本表更准确的规则是125,528条（118,329+7,199），加上平台64的10,402条，合计135,930条。

## 十、完整性扫描：确认没有第四组

为回答“是不是还有别的地方也错了”，对2018—2025年全部“年份×平台”单元（每年4—82个平台）做了两类扫描：

1. **高段集中**：月薪≥6万占比≥5%——年薪误录和量级放大都会落在这里；
2. **低段集中却无高值**：2.5万—6万占比≥10%、同时≥6万占比<5%。这类错误发生在“年薪只有3—6万”的低薪广告上，不会出现>10万的记录，只盯>10万会漏掉。

程序`code/python/42_scan_wage_anomalies.py`，结果`outputs/qc/wage_fix_v1_anomaly_scan.csv`，共命中12个单元：

|年份×平台|25万—6万占比|≥6万占比|结论|
|---|---:|---:|---|
|2019 平台64|9.8%|88.7%|已修正（÷10）|
|2018 平台11|4.1%|39.6%|已修正（÷12）|
|2021 平台72|11.0%|5.8%|已修正（÷12）|
|2019、2018 平台22|91.2%、52.2%|4.1%、1.2%|真实高薪：管理层岗位池（销售总监、财务总监、架构师），25,000/50,000/100,000为分档取值|
|2019—2024 平台13（6个年份）|11.6%—18.8%|0.4%—0.6%|真实高薪：技术岗位池（java、算法、产品经理），跨年占比稳定|
|2023 平台10|10.9%|0.3%|真实高薪：算法工程师、大数据、Python高级，高段相对低段配对倍数2.4|

结论：**没有第四组系统性错误**。这12个单元之外的平台，25万—6万与≥6万的占比都在1%以下，属于正常长尾。已修正的三组在`42`号程序里会自动识别为“已由修正规则覆盖”；新增命中单元如果不在`SOURCE_NOTES`里，扫描会输出`WAGE_FIX_V1_SCAN_GATE=REVIEW`，提示人工核查而不是自动改数。

## 十一、v2：把“面议”占位值置为缺失

2018年平台38有46条广告，最低月薪和最高月薪**都填成888,888**（888是“发发发”的吉利数），是平台把“薪资面议”写成占位值的做法。这46条涉及23家台州企业，岗位从门卫、叉车工、财务实习生到装配总监都有，与数值毫不相干；同样这23家企业同一年还有716条正常工资广告（中位4,750元）。全库5,235,461条中888,888只出现这46次，且两端完全相等——真实工资不会出现这种形态。

处理方式：**置为缺失，不除、不缩尾**。÷12得74,074仍是假数；缩到P99（4万）也是假数；唯一诚实的处理是承认“这批广告没报工资”。

|---|---|---|
| 记录数 | 5,235,461 | 5,235,461（行数不变） |
| 修正（÷12/÷10） | 135,930 | 135,930 |
| 置为缺失 | 0 | **46** |
| 有效工资记录 | 5,235,461 | 5,235,415 |
| 2018年平均月薪 | 9,892 | **9,861** |
| 2018年最大月薪 | 888,888 | **600,000** |

字段上与v1一致，另把`wage_fix_flag`扩展为三值：`0`未修正、`1`已修正（÷12或÷10）、`2`置为缺失；`wage_fix_rule`对缺失记录填`missing_placeholder_888888`；`wage_mid_orig`仍保留888,888，便于追溯原始数据。
