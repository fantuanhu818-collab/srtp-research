# B 的 Codex 项目说明

更新日期：2026-10-21

本文档供 B 及其 Codex 接手项目时阅读。开始工作前，先阅读本文件、`README.md`和`docs/目前进度.md`。

## 一、研究目标

本项目使用2018—2025年中国网络招聘数据，研究岗位要求AI技能时，招聘工资是否更高，以及这种关系在不同年份、职业、行业和地区是否存在差异。

现阶段只能把回归结果解释为相关关系。因果识别方案尚未确定，不得直接使用“AI技能导致工资提高”等表述。

## 二、目前处于哪一步

项目仍处于**原始数据审计阶段**，尚未开始正式清洗和正式回归。

已经完成：

- 原始文件盘点和字段结构的初步检查；
- 2018年和2022年的部分深入核对；
- Python处理数据、生成DTA、Stata读取DTA并运行回归的技术链路验证。

已经发现的主要问题：

- 2018年CSV有1,584,089条记录，DTA有1,584,088条记录；
- 2018年第1,131,491条记录的第24个字段异常非空；
- 2022年CSV和DTA均有356,114条记录，但内容尚未逐项核对；
- 已发现12,931条记录至少一个工资端点小于或等于0；
- 2,458个股票代码对应多个公司名称，企业识别规则需要进一步确定；
- 数据中没有稳定的招聘广告ID；
- 旧版AI关键词规则会把部分普通英文词误判为AI技能。

下一步先完成2018—2025年数据审计，再用2022年数据试运行完整清洗、变量构造和回归流程。

## 四、文件放在哪里

GitHub仓库只保存代码、规则、说明文档和小型结果，不保存原始招聘数据或大型中间数据。

```text
code/       Python、Stata和SQL分析程序
config/     路径示例；每台电脑的实际路径配置不上传
docs/       研究说明、分工、工作流和当前进度
outputs/    可以上传GitHub的小型审计表、回归表和图
scripts/    环境检查和程序运行工具
```

A电脑上的原始数据位于`D:\SRTP\分年份保存数据`，大型处理数据位于`D:\SRTP\工作数据`。B电脑可以使用不同路径，但必须复制`config/storage_paths.example.json`为`config/storage_paths.json`，并填写本机实际路径。`config/storage_paths.json`不会上传GitHub。

原始数据只能读取，不能由程序修改、移动、重命名或覆盖。大型CSV、DTA、Parquet、数据库、日志和临时文件不得提交到GitHub。

## 五、Codex完成任务的标准流程

```text
读取目前进度和相关程序
→ 编写或修改Python、Stata程序
→ 在电脑上实际运行
→ 保存数据、表格、图和日志
→ 核对记录数、缺失值和异常
→ 修正问题并重新运行
→ 用简明语言说明结果和下一步
```

任务不能停留在“已经写好代码”。完成时必须说明：使用了什么输入、运行了什么程序、生成了哪些文件、关键结果是什么、发现了什么问题、下一步是什么。

Python主要负责大规模数据审计、清洗和变量构造；Stata主要负责描述统计和回归。Python通过DTA文件把回归所需变量交给Stata。

## 六、Git协作规则

开始工作前先取得GitHub最新版本，完成一项可以独立检查的任务后再提交。提交前检查`git status`，确认没有原始数据、本机路径、临时文件或大型文件。

同一项程序在同一时间只由一人主改，另一人负责复核，避免两个版本互相覆盖。如果拉取时出现冲突，不要随意删除一方内容，应让Codex检查差异后再合并。

每次完成实质工作后，应同步更新`docs/目前进度.md`，写明：

- 谁完成了什么；
- 生成了哪些主要文件；
- 发现了哪些问题；
- 下一步由谁处理。

## 七、B的Codex首次接手时应做什么

1. 读取`README.md`、本文件、`docs/目前进度.md`和两份工作流文档。
2. 检查B电脑的数据位置和Python、Stata环境，不要直接照搬A电脑的绝对路径。
3. 取得现有AI关键词或旧版识别程序，先检查普通英文词误判和公司介绍误判。
4. 提出AI技能词典的分类与人工标注规则，保存为正式文件，并用小样本试标。
5. 在修改共享文件前取得最新版；完成后提交代码、规则、说明和小型结果，并更新目前进度。

遇到工资处理、企业识别、AI岗位定义、样本删除或回归设定等会影响研究结论的问题时，Codex应列出证据和可选处理方法，由A、B共同决定，不得自行把一种处理方法当作最终研究设定。
