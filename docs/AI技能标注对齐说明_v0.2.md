## 一、先分清三个层级

程序把AI词分成三层，筛词时要选的也是这三层。

|层级|意思|会不会让一条广告算“要求AI技能”（`ai_skill`=1）|例子|
|---|---|---|---|
|**1 严格**|意思基本唯一，就是AI|会，单独出现就算|深度学习、PyTorch、目标检测、ChatGPT|
|**2 条件**|常指AI，但也常有别的意思|会，但同一条广告里要有另一个严格词或条件词作证|机器视觉（也指工业检测设备）、Midjourney/AI绘画|
|**3 宽泛**|只说明和AI有关|不会，出现几个都不会；只计入宽泛版`ai_skill_broad`|人工智能、AI、CV、Transformer、AI工具|

几个例子：

- “负责机器视觉检测系统开发。” → 只有一个条件词，不算；
- “负责机器视觉检测，熟悉深度学习。” → 有严格词作证，算；
- “负责AI与自动驾驶相关产品规划。” → 两个都是宽泛词，不算。

## 二、第4步：筛词（今晚）

### 2.1 要做什么

打开`筛词表_A.xlsx`的“筛词表”页（B填`筛词表_B.xlsx`），对自己负责的260个候选词逐行在“筛选结果”列填：

- **1 严格**、**2 条件**、**3 宽泛**：加入词典，并选层级；
- **0 不加入**。

要说明理由的写在“备注”。不改其他列，不增删行。**填完之前两人不商量，也不看对方的表。**

**分工**：Excel版的“影响”和“负责”两列标明了每个词由谁筛。
- “影响”=重点的120个词（单独出现≥100条广告，决定了新增影响的98%）：“负责”=两人，**两人都筛**，要认真判断；
- 其余280个影响小的词按编号顺序交替分配，“负责”=仅A或仅B，**各140个，只由一人筛**。快速过，拿不准填0；
- 不归自己负责的行是灰色的，不用填（填了也不会被采用）。

每人共筛260个词。

### 2.2 判断顺序

对每个词，依次问三个问题：

1. **这个词本身是不是一种AI方法、模型、工具或任务？**（参照Acemoglu等2022年清单里的词，如机器学习、神经网络、目标检测）
   不是 → 填0。
2. **在例句里，它是不是对求职者的技能要求或岗位工作内容？**（而不是公司介绍、产品名称）
   大多数例句都不是 → 填0。
3. **它单独出现、旁边没有其他AI词时，是否仍然指AI？**
   看标“（单独出现）”的例句和“不含现有严格词的广告数”这一列。“（有其他AI词）”指这条广告别处有现有严格词，不一定在例句这一句里。
   - 单独出现也基本指AI → 可以选1；
   - 单独出现时经常有别的意思 → **最多选2**；
   - 只说明“和AI有关”，说明不了要求AI技能 → 选3。

### 2.3 直接填0的几类词

- 一般编程或数据技能：Python、SQL、数据分析；
- 一般IT词：大数据、云计算、Hadoop、Spark；
- 行业产品词：智能家居、智能硬件；
- 过于宽泛的词：算法、模型、智能、数学、视觉。

### 2.4 为什么要看“单独出现”

词典里加一个新词，真正多判为AI的，是**这个词单独出现**的广告；和别的AI词一起出现的广告，本来就已经判为AI了。

我们评估“宽泛词要不要升级”时就发现，相关度很高的词，单独出现时多数不是AI。例如：

- LoRA相关度91%，但单独出现时多指物联网无线通信；
- CV相关度59%，单独出现时常指充电模式、简历；
- Transformer单独出现时多指电力变压器。

所以第3个问题最关键。“共现相关度”只作参考，可以不同意，不同意时在备注写理由。

### 2.5 合并规则（填完后B运行程序）

- 重点词：两人都填1、2、3之一 → 加入，层级取更严的（1最严）；有一人填0 → 不加入；
- 单人负责的词：按负责人的结果，填0不加入；
- 只在120个重点词上报告两人“加入/不加入”的一致率和kappa值。

## 三、第6步：人工标注（11-19—21）

### 3.1 标注表长什么样

|编号|招聘岗位|职位描述|是否要求AI技能(1/0/9)|AI类型(traditional/generative/both)|备注|
|---|---|---|---|---|---|

表里**只有岗位名称和职位描述，看不到程序结果**。程序结果在`annotation_key.csv`，**标完之前不要打开**。

共360条，每人205条：其中50条两人都标，用来计算一致率，随机混在表里、不标出是哪50条；其余310条对半分。

### 3.2 什么时候标1

满足任一条：

1. 要求**掌握、熟悉、了解**某项AI技术、算法、框架或工具；
2. 岗位**职责**包括开发、训练、部署、调优AI模型或AI应用；
3. 要求**使用**AI工具（如ChatGPT、Midjourney）完成工作；
4. 把AI相关经验列为**优先或加分**条件。

### 3.3 什么时候标0

- AI只出现在公司介绍、产品介绍、行业描述里；
- “AI”实际是别的意思（Illustrator、自动插件等），CV是简历，Transformer是变压器；
- 泛泛提到AI，不构成技能要求，如“熟悉人工智能行业”。

### 3.4 什么时候标9

原文信息不够，确实分不出来，就标9，**不要猜**。例如“负责机器视觉相关工作”，看不出是算法开发还是设备调试。9不计入查准率和查全率，单独报告。

### 3.5 待定问题：先按现行口径标，备注写固定标签

这几类项目组还没最终决定。先按下表标，**备注一定要写固定标签**，以后口径变了可以直接挑出来改。

|情况|现行口径|备注标签|
|---|---|---|
|只要求“计算机、人工智能等相关专业”，没有技能要求|0|`仅专业`|
|数据标注、AI训练师等，只做简单标注，没有AI技术要求|0|`标注类`|
|只要求会用ChatGPT等AI工具处理办公事务|1，类型generative|`AI工具使用`|
|只有岗位名称是AI岗（如“机器学习工程师”），描述里没有AI词|**0**（11-19改，原为1）|`仅标题`|
|AI词前面有“无需、不要求、不需要”，或后面有“不作要求、非必须”|0|`否定`|

**为什么“仅标题”改为0**：与A的非AI技能口径一致，岗位名称不能单独决定技能变量（叫“软件工程师”但描述里没写软件技能，`skill_software`也是0）。否则AI技能和软件技能的定义不对称。程序同步修改：标题里的AI词只计入`ai_skill_broad`。全样本影响约415条广告（严格版1.349%→1.341%），见`outputs/qc/ai_negation_title_impact_v0.2.csv`。备注仍写`仅标题`，以后可以单独挑出来做稳健性检验。

**“不限”不算否定**：“OpenCV等不限”“AI能力(不限)”多是“不限于”的意思，照常判断。“者优先”照常标1。
|“算法工程师”，描述里没有任何AI词|0|`仅算法岗`|

### 3.6 AI类型怎么填

- `traditional`：机器学习、深度学习、计算机视觉、NLP、推荐算法等；
- `generative`：大模型、ChatGPT、AIGC、提示词、RAG、智能体等；
- `both`：两类都有；
- 标0或9时留空。

### 3.7 六个案例

|#|岗位|描述（改写）|标注|类型|备注|理由|
|---|---|---|---|---|---|---|
|1|视觉算法工程师|负责工业缺陷检测算法开发；基于深度学习进行目标检测模型训练与部署；熟悉PyTorch|1|traditional||职责含训练部署模型，要求熟悉PyTorch|
|2|销售代表|我们是一家专注于人工智能与大模型的领先企业。岗位职责：负责华东区域客户开发|0|||AI只在公司介绍|
|3|平面设计师|熟练使用PS、AI、CDR等设计软件|0||AI指Illustrator|同形异义|
|4|新媒体运营|负责公众号内容策划；能熟练使用ChatGPT、Midjourney辅助写作和出图者优先|1|generative|AI工具使用|要求使用AI工具，列为优先|
|5|软件工程师|计算机、人工智能等相关专业本科；熟悉Java、Spring Boot|0||仅专业|只有专业要求|
|6|视觉工程师|负责机器视觉相关工作，配合项目推进|9||机器视觉，看不出是算法还是设备|信息不足|

### 3.8 容易出错的地方

1. **只看原文，不猜程序会怎么判。** 标注是在检验程序，不能迁就它。
2. **以岗位为准，不以公司为准。** AI公司的会计岗标0。
3. **职责和要求都要看。** 职责写了“负责大模型应用开发”，即使任职要求里没有AI词，也标1。
4. **重叠的50条，标完前不讨论。** 否则一致率不准。

### 3.9 分歧怎么处理

1. 两人各自标完；
2. B运行程序算一致率和kappa，生成分歧清单；
3. 一起逐条讨论，给出最终标注；
4. kappa低于0.7，说明口径没对齐：先修改本说明，再重标重叠的50条。

这里处理的是**两人之间**的分歧。人工和程序之间的冲突（误判、漏判）按3.10和3.12节处理。

### 3.10 误判漏判的错误原因代码

`15_score_annotation.py`会生成`误判漏判清单.csv`（含原文，不进Git），最后两列“错误原因代码”“建议复核”留空，由Agent对照原文填写，另存为`误判漏判清单_已归因.csv`后再运行一次，程序汇总成`outputs/qc/ai_annotation_v0.2_error_codes.csv`。只能用下表的代码（程序会检查），每条填最主要的一个：

|代码|含义|对应的规则修改|
|---|---|---|
|`company_intro`|AI词只在公司或产品介绍里，程序没识别出是介绍|补公司介绍线索|
|`homonym`|同形异义：AI指Illustrator、CV指简历、Transformer指变压器等|加窄排除规则或降级|
|`generic_mention`|泛泛提到AI，不构成技能要求|降为宽泛词|
|`negation`|否定表达：无需、不要求、非必须|补否定词|
|`title_only`|只有岗位名称有AI词，描述里没有|（口径已定，记录即可）|
|`conditional_unpaired`|条件词没有搭配另一个AI词，程序未计入|考虑升级该条件词|
|`missing_term`|词典漏词或缺少常见写法|加词或加写法|
|`exclusion_overreach`|排除规则误伤了真正的AI要求|收窄排除规则|
|`exclusion_missing`|缺少应有的排除规则|加窄排除规则|
|`tool_use`|只是使用AI工具，口径待定|待项目组决定|
|`label_dispute`|人工标注可能有误|不改标注，交两人复核|

第7步“按事先定好的规则微调一次”就按这张汇总表决定改哪些规则：同一代码出现多次的才改，只出现一次的记录在案、不改。

### 3.11 交回前检查（程序自动做）

`15_score_annotation.py`读入标注表时先检查，不通过就停下并列出编号，不会自动改：

- 列名和列顺序与发出时一致；编号与发出的一致，没有增删或重复；
- 1/0/9一列没有空白，只有0、1、9；
- 标1的都填了AI类型（traditional/generative/both）；标0或9的AI类型为空。

自己交回前也请检查：备注里的固定标签只用3.5节那几种；行顺序没动；文件名没改。

### 3.12 人工和Agent各做什么

参照A的职业复核：**人只做核心判断，Agent补其余部分，Agent不能改人的判断。**

|环节|人做|Agent（程序）做|
|---|---|---|
|标注|1/0/9、AI类型、备注标签（只看原文）|—|
|检查|—|交回前检查（3.11节）|
|一致性|两人讨论分歧，填`分歧裁定.csv`|算一致率、kappa，列分歧清单|
|误判漏判|—|对照原文填错误原因代码；认为人工可能标错的，只在“建议复核”写原因，**不改人工标注**|
|改规则|两人确认要改哪些（3.10节）|按确认结果改词典和排除规则、补单元测试、全量重跑|

**标注表本身的结构不变**，已经发出去的标注表照常使用。

## 四、建议：正式标注前先试标10条

正式标注前，两人各自标同样的10条真实广告（不计入正式样本），然后对答案。对不上的地方先讨论清楚，再补充进本说明第3.5节。这样可以大大降低正式标注kappa不达标、要返工的风险。
