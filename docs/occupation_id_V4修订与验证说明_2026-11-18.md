# occupation_id V4修订与验证说明

## 1. 本轮目标

V4不改变现有37个职业组，主要修正“岗位名称对应标准职业名称”的第一环节，并保证标准职业名称能够唯一映射到37类代码。

## 2. 人工反馈整理

- 原分层复核样本：1080条；
- 可作为回归测试金标准：1038条；
- 待团队裁决：41条，其中35条来自补查表的“建议复核第一环节”，另有6条在规则回测中发现人工标签与职位描述明显冲突；
- 信息不足并保留Z99：1条；
- A组89条“职业名称正确但代码仍为Z99”的记录，已按现有职业名称词典补齐代码。

待裁决记录不进入自动别名词典，防止把有争议的人工判断写成全量规则。

## 3. V4分类顺序

1. 清理职位编号、公司名称、招聘广告、福利信息和职级词；
2. 使用安全的人工确认别名；
3. 使用上下文规则处理安全、运维、研究员、测试、产品工程师、金融风控和英文缩写等歧义；
4. 使用无歧义职业名称词典做精确匹配；
5. 使用原关键词规则，但取消“初级分类自动兜底”；
6. 对剩余岗位使用相似度不低于90、组间分差不低于5的高门槛模糊匹配；
7. 信息不足时保留Z99，并生成复核提示。

## 4. 已知样本回归测试

在1038条可确认记录上：

- V3代码与人工最终代码一致：697条，67.15%；
- V4代码与人工最终代码一致：1038条，100%；
- `fuzzy_false_match`、`missing_alias`、`normalization_error`等已知问题均通过回归检查。

这里的100%只说明已知错误得到修复。人工确认别名来自同一批样本，因此不能把它解释为面对新数据的准确率。

## 5. 独立验证样本

从未参与规则开发的2018—2025年数据中抽取300条：

|V4方法|条数|
|---|---:|
|上下文规则|80|
|人工确认别名|60|
|词典精确匹配|40|
|关键词规则|50|
|高分模糊匹配|40|
|Z99未分类|30|

人工判断只评价“V4标准职业名称是否正确”。若判断正确，可保留预填职业代码；若错误或无法判断，需要修改职业代码并写明正确职业名称和依据。

## 6. 全量运行条件

暂不运行2018—2025年全量V4。独立验证完成后，需要：

1. 计算第一环节职业名称准确率和第二环节37类代码准确率；
2. 分别检查六种分类方法，不能只看总体平均；
3. 将新错误整理成通用规则，避免按来源记录ID硬编码；
4. 重新回测已知样本与独立样本；
5. 通过后生成全量V4特征表，并比较各年份职业分布和Z99比例。
