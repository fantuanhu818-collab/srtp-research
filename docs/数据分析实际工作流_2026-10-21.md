# Codex数据分析实际工作流

更新日期：2026-10-21

## 一、Codex怎样完成数据分析

Codex不只是编写代码，而是完成整个执行过程：

```text
A或B提出研究任务
→ Codex编写Python或Stata程序
→ 在电脑后台实际运行
→ 保存数据、表格、图形和日志
→ 检查记录数、变量和异常
→ 修正问题并重新运行
→ 用简明语言解释结果和下一步
```

A、B不需要亲自编程，但需要决定AI岗位定义、工资处理方法、回归设定和结果解释等研究问题。

## 二、Python怎样把数据交给Stata

本项目通过数据文件连接Python和Stata，不需要复杂的软件接口：

```text
原始CSV或DTA
    ↓ Python：审计、清洗、构造变量
完整Parquet数据
    ↓ Python：选出回归所需变量
Stata 118格式DTA
    ↓ Stata：描述统计和回归
回归表、图形和日志
```

### Python阶段

Python负责处理大规模招聘数据，包括检查字段和记录数、清洗工资和日期、识别AI技能、标记重复与异常，并生成分析变量。

Codex将程序保存为`.py`文件并实际运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_python_task.ps1 `
  -ScriptPath code/python/任务名称.py
```

运行后至少生成：

- Parquet完整数据；
- 提供给Stata的DTA数据；
- 记录数、缺失值和异常值检查表；
- Python运行日志。

Codex必须读取这些结果，并说明输入多少条、输出多少条、发现了哪些异常。

### Stata阶段

Codex将统计和回归命令保存为`.do`文件，然后在后台调用本机Stata/SE 18：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_stata_task.ps1 `
  -DoFile code/stata/任务名称.do `
  -ExpectedLog outputs/analysis/任务名称.log
```

Stata读取Python生成的DTA，检查样本和变量，运行统计或回归，并保存回归表、模型样本数、图形和日志。只有Stata正常退出、生成本次日志且日志包含`STATA_TASK=PASS`，任务才算运行成功。

这条“Python生成DTA—Stata读取—执行回归”的链路已经在本机验证通过。

## 三、一次工资回归怎样完成

例如研究“要求AI技能的岗位工资是否更高”：

1. **准备数据**：Codex用Python生成工资及其对数、AI技能、学历、经验、企业、职业、城市和月份等变量。
2. **质量检查**：核对记录数、工资异常、缺失值和AI岗位数量；检查通过后导出DTA。
3. **运行回归**：Codex调用Stata，依次运行：

```text
模型1：只比较AI岗位和非AI岗位
模型2：加入学历、经验和其他技能
模型3：加入企业固定效应
模型4：加入职业、城市和时间固定效应
```

固定效应用于控制不同企业、职业、城市或时期本身存在的平均差异。

4. **解释结果**：Codex说明每个模型的样本数、AI技能系数、加入控制变量后的变化、统计显著性和数据局限。现阶段结果首先解释为相关关系，不能直接解释为因果关系。

任何正式结果都必须对应一份程序、一版数据和一份运行日志。

## 四、怎样向Codex下达和验收任务

任务说明应包含：研究问题、输入数据、需要的输出和操作限制。例如：

```text
请检查并清洗2022年招聘数据。原始数据只能读取，不能修改或覆盖。
请编写并实际运行Python程序，保存Parquet、DTA、数据检查表和日志。
请核对输入和输出记录数，异常记录先保留并添加标记，不要直接删除。
完成后用简明语言说明结果、问题和下一步。
```

要求回归时补充：

```text
请把Stata命令保存为do文件并实际调用本机Stata运行。
保存回归表、每个模型的样本数和日志，不要把相关关系解释为因果关系。
```

A、B验收时检查：程序是否保存并实际运行、输出文件是否存在、记录数能否核对、Codex能否解释结果和异常。缺少程序、输出或日志，任务就没有完成。
