# 工资变量清洗方案

版本：wage_fix_v4　日期：2026-11-19　负责人：A线
数据基础：`cleaned_v1`（5,235,461条，2018—2025）　回归底表：`confirmed_core_v2`（5,235,398条）

本文是工资变量的完整口径说明：从原始字段怎么合成、有哪些已知错误、每条错误怎么判定、修成什么样、还剩什么限制。**`cleaned_v1` 与 `confirmed_core_v2` 全程只读，未改动一个字符**；所有修正结果单独存放在特征表 `wage_fix_v1 → v4`，通过 `source_record_id` 与底表一一连接。

## 一、工资变量是怎么来的

### 1.1 原始字段

数据商交付的每条招聘广告有 `最低月薪`、`最高月薪` 两个字段，单位应为「元/月」。

### 1.2 合成规则（`04_clean_recruitment_data.py`）

| 情形 | 处理 |
|---|---|
| 两个端点都能转数值且 >0 | `月薪代表值 = (最低月薪 + 最高月薪) / 2` |
| 只有一端有效 | 取有效的那一端 |
| 两端都无效 | 删除整条记录（共489,637条） |
| 上下限颠倒 | 交换后计算（174条） |

即**区间中点**。只有两个数时，中位数与均值相等，所以这个值既是中点、也是两端点的中位数。

验证：全样本 5,235,461 条中，双端点区间 5,118,168 条、双端点相等 20,186 条、单端点 93,981 条；**偏离上述规则的记录为 0**。

### 1.3 对数

- `confirmed_core_v2.ln_wage = ln(wage_mid)`（自然对数，旧口径，含错值）
- `wage_fix_v*.ln_wage_orig = ln(原值)`
- `wage_fix_v*.ln_wage_fixed = ln(修正后月薪)` ← **回归与描述统计用这个**
- 缺失记录的 `wage_mid_fixed` 与 `ln_wage_fixed` 同时为空

## 二、问题诊断：六类已知错误

| # | 类型 | 年份×平台 | 规模 | 判定证据 |
|---|---|---|---:|---|
| 1 | 年薪误录为月薪 | 2018 平台11 | 118,329 | 3—6万区间2018年有5,772条、2019年0条；同企同岗位倍数12.5；÷12后中位11,250与正常组9,000同量级 |
| 2 | 年薪误录为月薪 | 2021 平台72 | 7,199 | 6万以上同企同岗位倍数12.57；3—6万倍数仅2.29（属真实高月薪），故门槛定6万 |
| 3 | 整平台放大约10倍 | 2018、2019 平台64 | 547 + 9,855 | 与2020年同平台分位结构拟合，10倍误差最小（SSE 0.081 vs 9倍0.125、11倍0.137、12倍更差）；同企业2019/2020中位比10.77 |
| 4 | “面议”占位值 | 2018 平台38 | 46 | 两端均为888,888；23家台州企业，岗位从门卫到装配总监；全库仅出现这46次 |
| 5 | 修正后仍>10万 | 全样本 | 2,982 | 226条有年薪特征（同企同岗位9—13倍），2,612条无对照，94条倍数>15 |
| 6 | 日薪/时薪记进月薪字段 | 2018 平台20、平台77、2021 平台28等 | 10,649 | 平台20的1,235条能与文本“底薪X元”对上，倍数中位20.2≈21.75；平台77文本“21元/小时”“25元/小时”与字段一致；平台28出现833.33=10000/12的非整数 |

判据方法：**同企业同岗位配对倍数**。同一家公司在同一年为同一岗位名称发布多条广告时，若高值组正好是低值组的12倍，即可判定高值组是年薪写进了月薪字段。该方法不依赖广告正文（正文只有0.4%提到“年薪”）。

平台11的阈值为什么是3万而不是早期诊断中的6万：2018年平台11在3—6万区间有5,772条，而同一平台2019年该区间为0条、6万以上也为0条；同时2—3万区间两年分别为12,198和12,739条（正常月薪）。用6万门槛会漏掉这5,772条年薪。

## 三、清洗规则（已执行）

### 3.1 高值端规则

| rule_id | 年份 | 平台 | 条件 | 动作 | 条数 |
|---|---|---|---:|---|---:|
| `annual_div12_p11_2018` | 2018 | 平台11 | 月薪代表值 ≥ 30,000 | ÷12 | 118,329 |
| `annual_div12_p72_2021` | 2021 | 平台72 | 月薪代表值 ≥ 60,000 | ÷12 | 7,199 |
| `scale_div10_p64_2018` | 2018 | 平台64 | 月薪代表值 ≥ 10,000 | ÷10 | 547 |
| `scale_div10_p64_2019` | 2019 | 平台64 | 月薪代表值 ≥ 10,000 | ÷10 | 9,855 |
| `missing_placeholder_888888` | 全部 | 全部 | 两端同时等于 888,888 | 置缺失 | 46 |
| `annual_div12_extreme` | 全部 | 全部 | 未修正且 100,000 < 月薪 ≤ 1,200,000 | ÷12 | 2,896 |
| `missing_unfixable_extreme` | 全部 | 全部 | 月薪 > 1,200,000，或已被÷12过一次且仍 > 100,000 | 置缺失 | 86 |

### 3.2 低值端规则（v4新增，日薪/时薪换算）

判定顺序自下而上，命中即停：

| 优先级 | rule_id | 条件 | 动作 | 条数 |
|---:|---|---|---|---:|
| 1 | `missing_tiny_value` | 0 < 月薪 ≤ 10 | 置缺失 | 261 |
| 2 | `hourly_to_monthly` | 职位描述含“元/小时”或“每小时” | ×174 | 见下 |
| 3 | `daily_to_monthly_by_text` | 职位描述含“元/天”或“元一天” | ×21.75 | 见下 |
| 4 | `hourly_to_monthly_by_magnitude` | 无单位文本且 月薪 < 60 | ×174 | 见下 |
| 5 | `error_div12_to_monthly` | 2021 平台28，且 60 ≤ 月薪 < 1,000 | ×12 | 见下 |
| 6 | `daily_to_monthly_by_magnitude` | 其余 60 ≤ 月薪 < 1,000 | ×21.75 | 见下 |
| 保险 | `missing_over_cap` | 换算后 > 100,000 | 置缺失 | 2 |

换算依据：日薪 × **21.75**（法定月计薪天数）；时薪 × 8小时 × 21.75天 = **×174**。

规则机器可读文件：`config/wage_fix_rules_v1.json`、`v2`、`v3`、`v4`。

### 3.3 为什么平台64用÷10而不是÷12

它不是年薪，是整平台量级错误。三条证据：
1. 2019年平台64只有5条低于1万元，整段上移；与2020年同平台分位结构拟合，10倍最优（12倍明显更差）；
2. 同企业在2019与2020的中位月薪之比为10.77倍（IQR 8.75—13.08）；
3. 平台内“高值 vs 正常值”配对仅1.4倍，说明不是“一半年薪一半月薪”的双峰，而是整批被放大。

### 3.4 为什么平台38用置缺失而不是÷12

888,888÷12 = 74,074，缩尾到P99（4万）也还是假数。这批广告本质是“没报工资”，唯一诚实的处理是视为缺失（等同“面议”）。

### 3.5 为什么v3的86条置缺失

- 13条原值>120万，÷12后仍超10万；
- 73条已被v1按年薪÷12过一次、原值280万—800万，再除一次等于÷144，缺乏依据；
- 典型：2020平台28“cto”969万、2019平台13“电商运营专员”800万、2021平台1“快递员”750万、2021平台1“肯德基服务员”450万。

### 3.6 为什么低值端要先看文本、再看量级

- 文本写着“21元/小时”，字段就是21，最可靠；
- 没有文本时，用物理量级判断：60元以下不可能是日薪或月薪，只能是时薪；60元以上按日薪（平台20的“底薪/字段”倍数中位20.2，平台77的60元以上段文本以“元/天”为主，比例15:1）；
- 平台28的特殊之处：出现833.33（=10000/12）、666.67（=8000/12），是“月薪被误除以12”的反向错误，用×12还原；但它的11—59元段经×12仍是132—708元，不合常识，故归入时薪（×174）。

## 六、剩余限制（写论文时必须声明）

1. **样本为上市公司招聘广告**，不是全国劳动者；
2. **只保留明码标价的广告**：删除了489,637条双端点无效（多为“面议”）的记录，会系统性剔掉部分低端岗位；
3. **工资是广告报价区间中点**，税前、不含年终奖，高于实际到手；
4. **名义工资**，未做通胀平减；跨年比较建议用年份固定效应或按CPI平减；
5. **城市、企业为初版口径**：`city_id` 为保守标准化、`firm_id` 为六位股票代码（上市公司集团层级），不等于实际招聘企业；
6. **77条换算后仍低于1,000元**（326—960元）：来自极小日薪/时薪的兼职广告，属真实兼职收入，按原样保留；
7. **日薪/时薪的换算是等价月薪**：兼职岗位实际工作天数少于21.75天，换算值代表“若全职的等效月薪”，不是实际月收入。

| `wage_fix_action` | none / divide / multiply / set_missing |
| `wage_fix_version` | `wage_fix_v4` |

### 7.2 合并

```python
import pandas as pd
core = pd.read_parquet(r"D:\SRTP\工作数据\features\confirmed_core_v2\jobs_2018_confirmed_core.parquet")

df = core.merge(fix, on="source_record_id", how="left", validate="one_to_one")
df["wage"] = df["wage_mid_fixed"]
df["ln_wage2"] = df["ln_wage_fixed"]
```

```stata
merge 1:1 source_record_id using "wage_fix_v4.dta", keep(master match) nogen
gen wage     = wage_mid_fixed
gen ln_wage2 = ln_wage_fixed
```

- 缺失记录（395条）工资与对数同时为空，回归会自动剔除；

## 附录：诊断方法速查

**配对倍数法**：对同一 `(年份, 平台, 企业名称, 招聘岗位)` 组合，分别取“高值组”与“低值组”的中位月薪，比值接近12即判定高值组为年薪；比值接近10判定为量级放大；比值接近21.75判定为日薪；比值接近174判定为时薪。

**完整性扫描**（`42_scan_wage_anomalies.py`）：对2018—2025全部“年份×平台”单元做两类筛查——①月薪≥6万占比≥5%；②2.5万—6万占比≥10%且≥6万占比<5%（后者专门抓“年薪只有3—6万、不会出现>10万记录”的隐蔽错误）。命中12个单元，其中3个已修正、9个经核查为真实高薪（平台22管理层池、平台13技术岗、平台10算法岗）。
