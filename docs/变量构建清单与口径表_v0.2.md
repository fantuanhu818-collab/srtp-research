# 变量构建清单与口径表 v0.2

更新日期：2026-11-16  
适用数据：`D:\SRTP\工作数据\curated\cleaned_v1`  
当前目标：形成描述统计和基准工资回归所需的最小分析数据集。

## 一、范围

本版只列当前需要构建的核心变量，不再把清洗标记、人工审核字段、异质性变量和所有可能的稳健性变量都计入研究变量。

- 一行仍代表一条招聘广告，不代表一名劳动者。
- 原始字段、清洗标记和来源记录ID继续在后台保留，但不算作论文研究变量。
- AI技能识别方案由负责AI技能工作的队友设计。本表只规定数据交接接口，不替队友确定词典、模型或分类规则。
- 职业AI暴露度、企业所有制、城市层级和ChatGPT冲击等变量，等对应扩展分析开始时再构建。

## 二、基准回归核心变量

基准模型计划比较：在学历、经验、其他技能、企业、职业、城市和时间尽量可比的条件下，要求AI技能的招聘广告是否发布更高工资。

|序号|变量名|中文含义|构造口径|在基准回归中的作用|负责人|状态|
|---:|---|---|---|---|---|---|
|1|`wage_mid`|月薪代表值|直接使用清洗数据中的“月薪代表值”；双端点取均值，单端点取有效值|因变量的水平值|数据分析线|已有|
|2|`ln_wage`|月薪代表值对数|`ln(wage_mid)`，只对正值生成|基准回归因变量|数据分析线|已构建|
|3|`ai_skill`|是否明确要求AI技能|由队友的AI识别方案生成，要求AI技能为1，否则为0|核心解释变量|AI技能线|待交付|
|4|`education`|标准学历要求|“其他/其它”归为“不限”；“以上/0/误填地点”记录删除；其余统一为六类|控制学历要求差异|数据分析线|已构建v2|
|5|`experience`|标准经验要求|将原始经验统一为“不限/应届、1年以内、1—3年、3—5年、5年以上”|控制工作经验要求差异|数据分析线|已构建|
|6|`skill_software`|软件/编程技能要求|从职位描述识别通用软件和编程技能，不包含AI技能本身|控制技术岗位本身较高工资|技能规则待协作|待讨论|
|7|`skill_cognitive`|认知/分析技能要求|识别分析、研究、问题解决等要求|控制岗位复杂程度|技能规则待协作|待讨论|
|8|`skill_social`|沟通/社交技能要求|识别沟通、协作、谈判等要求|控制通用软技能差异|技能规则待协作|待讨论|
|9|`firm_id`|企业标识|初版使用补齐六位的上市公司股票代码|上市公司集团固定效应和聚类|数据分析线|已构建初版|
|10|`occupation_id`|统一职业分类|按两层职能分类和关键词优先级规则映射岗位名称|职业固定效应|数据分析线|2022试运行待修订|
|11|`city_id`|标准工作城市|初版保守统一城市名；纯省份、无法可靠归属的区县和多地暂缺失|城市固定效应|数据分析线|已构建初版|
|12|`year_month`|招聘发布年月|由招聘发布日期生成月份编码|时间固定效应|数据分析线|已构建|
|13|`sample_base`|基准共同样本|上述基准变量均满足模型要求时取1|保证渐进模型使用同一批样本|数据分析线|待构建|

当前基准分析只需要以上13个变量。其中`skill_software`、`skill_cognitive`和`skill_social`是否由AI技能线一并设计，需由两位成员确定；如果队友只负责AI技能识别，数据分析线再单独制定这三类非AI技能的简化词典。

## 三、AI技能线的交接接口

AI技能线可以自行决定关键词、正则表达式、语义方法、传统AI与生成式AI分类及人工标注方案。合并回归数据时，至少需要交付：

|交付字段或材料|最低要求|是否进入基准回归|
|---|---|---|
|`source_record_id`|与清洗数据中的来源记录ID完全一致且唯一|仅用于合并|
|`ai_skill`|0/1变量；不得把文本缺失或无法判断的记录自动编码为0|是|
|AI规则版本|能说明本次结果使用哪一版词典或模型|否|
|人工验证报告|说明抽样方法、样本量、主要误判和漏判；尽量报告查准率和查全率|否|

以下内容可以由队友完善，但不是数据分析线当前必须先构建的变量：

- 传统AI与生成式AI的细分；
- 命中词、命中位置和文本证据；
- AI技能数量或强度；
- 多版本词典的稳健性结果。

这些字段可保留在AI特征文件中。基准回归数据首先只读取`ai_skill`。

## 四、暂不构建的扩展变量

以下变量与研究设计有关，但当前不进入基准数据集。等基准回归跑通后，再按实际需要逐项增加。

|变量|对应研究问题|何时再构建|
|---|---|---|
|`post_chatgpt`|ChatGPT发布前后AI技能工资差异是否变化|完成基准回归后进行时间扩展时|
|`ai_exposure`|高AI暴露职业的AI技能工资差异是否更大|确定职业分类和外部暴露度来源后|
|`industry_id`|行业异质性|开展行业分组分析时|
|`city_tier`|城市层级异质性|确定固定城市层级来源后|
|`ownership`|国企、民企、外资异质性|找到可按股票代码匹配的外部数据后|
|`real_wage`|跨年度实际工资趋势|正式比较长期工资趋势且确定CPI来源后|
|`vacancy_count`|按招聘人数衡量岗位需求|需要人数加权结果时|
|`description_length`、`skill_count`|文本长度和技能数量稳健性|基准结果完成后|

暂不构建不代表这些问题被取消，只表示不让扩展分析阻塞当前基准回归。

## 五、后台保留但不算研究变量的字段

以下字段继续保存在完整Parquet中，用于追溯和质量检查，不进入“13个核心变量”的计数：

- `source_record_id`、`content_id`；
- 最低月薪、最高月薪及其原始值；
- 工资清洗方式、工资或日期交换标记；
- 学历和结束日期缺失标记；
- 重复组记录数；
- 原始企业、岗位、城市、学历、经验和职位描述。

## 六、已确认的初版口径与剩余讨论项

### 1. 企业固定效应：中期先使用上市公司集团层级

项目组已确认中期先采用六位股票代码：

- 去除小数尾缀并补齐六位；
- 固定效应解释为“上市公司集团固定效应”，不能写成精细招聘企业固定效应；
- 该方案仍是不完善的初版，后期构建招聘企业实体ID并做稳健性检验。

### 2. 城市：中期先使用保守标准化

- 统一城市简称、带“市”后缀、直辖市和明确的地级行政区；
- 海外单列；纯省份、全国/不限/多地和无法可靠归属的区县保持缺失；
- 不用公司注册地址替代工作城市；
- 该方案仍是不完善的初版，后期引入行政区划表并人工复核。

### 3. 职业分类做到多细

当前岗位名称约有218万个不同写法，不能直接作为职业固定效应。第一版只需形成稳定的职业大类和适度细分类，不追求一次建立极细的职业编码。

### 4. 三类非AI技能由谁负责

为了避免两条工作线重复识别文本，需要确认队友是否连同软件、认知和社交技能一起设计。如果没有，数据分析线只为这三类建立简化、可人工检查的词典，不扩展到十几类技能。

## 七、执行顺序

1. 数据分析线已生成`wage_mid`、`ln_wage`、`education`、`experience`、初版`firm_id`、初版`city_id`和`year_month`，并通过独立复核。
2. `occupation_id`已完成2022年诊断性试运行，但覆盖率只有70.50%且尚未人工复核；先修订规则，不直接全量构建。
3. AI技能线按本文件的交接接口交付`source_record_id + ai_skill`及验证说明。
4. 双方确认三类非AI技能的负责人并生成相应变量。
5. 合并后生成`sample_base`，核对样本量和缺失值。
6. 完成描述统计和渐进式基准回归。
7. 基准结果通过复核后，再决定先做时间变化还是AI暴露度扩展。
