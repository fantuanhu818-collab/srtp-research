# occupation_id 人工复核 B 组交接说明

## 一、任务背景

本项目正在构建在线招聘数据的 `occupation_id` 职业类型变量。现有程序先把招聘岗位名称匹配到一个标准职业名称，再把标准职业名称映射到项目使用的 37 个职业组。

职业分类分成两个环节：

1. 第一环节：招聘岗位名称是否匹配到了正确的标准职业名称。
2. 第二环节：确认后的标准职业名称属于 37 个职业组中的哪一组。

人工复核中的“正确、错误、无法判断”只评价第一环节，不评价程序给出的职业代码。

例如：

- 原始岗位名称：`测试工程师`
- 程序匹配名称：`测试开发工程师`
- 程序职业代码：`Z99`

如果人工认为“测试开发工程师”可以正确表达该岗位，第一环节仍应标记为“正确”。第二环节再把“测试开发工程师”映射为 `D04 软件测试与质量保障`。

## 五、B 的人工复核任务

### 5.1 主要查看字段

B 主要查看以下字段：

- `原始岗位名称`
- `标准化岗位名称`
- `程序职业名称`
- `匹配到的名称`

### 5.2 第一环节判断标准

在 O 列“人工判断”中填写以下三种结果之一。

#### 正确

程序“匹配到的名称”能够合理、准确地表达该岗位的主要职业。

这里不考虑程序职业代码是否为 `Z99`。如果职业名称正确但程序代码为 `Z99`，仍然填写“正确”。

#### 错误

程序“匹配到的名称”明显不是这个岗位的职业名称。

例如：

- `风险管控岗`匹配为`仓管员`；
- `Python开发工程师`匹配为`PHP开发工程师`；
- `跟车员保底9K+带薪培训`匹配为`培训专员`。

#### 无法判断

仅凭岗位名称无法可靠判断程序匹配名称是否正确。

不要为了完成进度强行猜测。后续由 Agent 结合职位描述辅助判断。

### 5.3 B 不需要完成的内容

B 不需要：

- 判断职业代码；
- 修改程序职业代码；
- 查询 37 个职业组；
- 填写复杂的判断依据；
- 修改“补查结果”工作表。

B 的核心任务只是完成 O 列的第一环节人工判断。

## 六、B 的 Agent 处理规则

B 完成人工判断后，Agent处理第二环节。Agent不得修改 B 已经填写的 O 列。

### 6.1 人工判断为“正确”

处理逻辑：

```text
最终标准职业名称 = 匹配到的名称
最终职业代码 = 在职业名称—37类映射表中查询得到的代码
```

填写要求：

- P 列填写该职业名称对应的 37 类代码；
- Q 列留空；
- R 列一般留空；如发现标题与职位描述明显冲突，可填写“建议复核第一环节”；
- S 列填写审核者或 Agent 标识；
- 不得直接复制程序原代码中的 `Z99`。

人工确认职业名称正确以后，不再使用模糊匹配 90 分门槛。模糊匹配门槛只负责决定是否需要人工复核，不能否定人工复核结果。

### 6.2 人工判断为“错误”

Agent需要：

1. 根据`来源记录ID`查询原始职位描述；
2. 判断正确的标准职业名称；
3. 将标准职业名称映射到 37 个职业组；
4. 在 P 列填写正确职业代码；
5. 在 Q 列填写错误原因代码；
6. 在 R 列填写“正确职业名称＋简要判断依据”；
7. 在 S 列填写 Agent 或审核人标识。

如果人工已经判断为错误，但没有写出正确职业名称，由 Agent 补查。

### 6.3 人工判断为“无法判断”

Agent可以把职位描述作为辅助信息：

- 如果职位描述能够确定职业，填写正确职业名称和职业代码；
- 如果职位描述仍然不足，P 列填写 `Z99`；
- R 列必须说明为什么无法可靠判断；
- 不得在没有理由的情况下保留 `Z99`。

### 6.4 疑似人工误标

如果 B 标记为“正确”，但职位描述与程序匹配名称明显冲突，Agent不得擅自修改 O 列。

应在 R 列填写：

`建议复核第一环节：具体原因`

同时在现有`补查结果`工作表中记录，等待 A、B 两组共同讨论。

## 七、错误原因填写口径

Q 列使用工作簿现有的错误原因代码：

| 错误原因代码 | 含义 |
|---|---|
| wrong_function | 主要工作职能判断错误 |
| generic_title | 岗位名称过于宽泛 |
| multiple_functions | 同时包含多个职业职能 |
| keyword_conflict | 多个关键词规则发生冲突 |
| fuzzy_false_match | 字面相似但职业含义不同 |
| normalization_error | 岗位名称标准化或广告词处理错误 |
| missing_alias | 缺少常见别名、缩写或完整短语 |
| should_remain_z99 | 信息不足，应继续保留 Z99 |

1. 按`来源记录ID`合并 A、B 两组结果；
2. 检查是否存在重复记录和冲突判断；

4. 汇总人工确认的职业名称—37类映射；
5. 形成职业别名词典、标准化规则、关键词规则、排除规则和上下文规则；
6. 生成职业分类 V4 候选规则。

不要通过复制粘贴整行来合并，以免错位或破坏字段格式。合并时以`来源记录ID`为主键。

## 十二、完成后能否重新运行数据

可以。人工复核的目的就是用人工反馈修正职业分类规则并重新运行数据。

但不建议收到B组文件后立即运行全部 2018—2025 年数据。正确流程是：

```text
A、B人工复核完成
        ↓
合并人工反馈并处理冲突
        ↓
更新标准化规则、职业名称词典和分类规则
        ↓
先对1080条分层样本重新运行
        ↓
比较V3与V4的准确率、Z99比例和典型错误
        ↓
确认规则改进且未产生新的系统性错误
        ↓
再运行2018—2025年全量数据
```

这一阶段不需要训练模型。人工反馈主要用于完善：

- 岗位名称标准化规则；
- 职业名称别名词典；
- 关键词和完整短语规则；
- 排除词规则；
- 上下文判断规则；
- 人工确认结果的第二阶段回写逻辑。
